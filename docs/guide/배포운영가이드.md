# Assu 배포/운영 가이드

> 최종 수정: 2026-11-02 · 수정자: 2ghrms

K3S 클러스터 + ArgoCD GitOps로 운영한다. 이 문서는 구조를 요약하고, 운영 중 자주 하는 일을 정리한다.
- 운영 중 자주 하는 일: 접속, 로그, DB 확인, 배포, 롤백, 장애 대응
- 매니페스트의 설계와 트러블슈팅 기록은 비공개 `ASSU_BE_manifest` 레포의 `README.md`에 있다.

> **이 레포는 공개 저장소다.** 아래 정보는 문서에 쓰지 않는다.
> - 대상: IP, 인스턴스 ID, RDS 주소·계정, 키 경로
> - 보관 위치: 각자 로컬의 `~/.assu/infra.env`(레포 밖)
> - 필요한 키 목록은 [부록](#부록-infraenv-키-목록)에 있다. 값은 팀원에게 따로 받는다.

## 1. 구조

### 배포 파이프라인
```text
develop/main 머지
  → GitHub Actions: 이미지 빌드 → DockerHub push (태그 = commit SHA)
  → ASSU_BE_manifest의 overlays/{dev,prod}/deployment-patch.yaml 이미지 태그 커밋
  → ArgoCD가 감지해 클러스터에 반영 (selfHeal)
```
- 배포는 사람이 서버에 들어가 명령을 치는 일이 아니다. **git 커밋**이 배포를 일으킨다.
- `ASSU_BE_manifest`가 "클러스터에 무엇이 떠 있어야 하는가"의 유일한 정답(source of truth)이다.
- 워크플로의 동시 실행 정책:

  | 워크플로 | 트리거 | concurrency | 이유 |
  |---|---|---|---|
  | `cd-dev-argocd.yml` | `develop` 머지 | `cancel-in-progress: true` | 연속 머지 시 마지막 커밋만 배포한다. 늦게 끝난 이전 빌드가 최신 태그를 덮어쓰는 것을 막는다 |
  | `cd-prod-argocd.yml` | `main` 머지 | `cancel-in-progress: false` | 순서대로 실행한다 |

### 노드 3대

| 노드 | 사양 | 역할 |
|---|---|---|
| control | t3.small | K3S 컨트롤 플레인 + ArgoCD. taint로 앱 워크로드를 막는다 |
| prod | t3.medium | 운영 앱, Redis, RabbitMQ, Traefik |
| dev | t3.small (부하테스트 중 임시로 t3.medium) | 개발 앱, Redis, RabbitMQ, Traefik |

- 노드는 라벨 `role=control/prod/dev`로 구분한다. 각 워크로드는 `nodeSelector`로 자기 노드에 고정된다.
- 노드에 EIP가 없다.
  - **stop/start하면 공인 IP가 바뀐다.** 이때 가비아 DNS의 A 레코드를 갱신해야 한다.
  - 재부팅(reboot)은 IP가 유지된다.
  - 현재 IP는 `kubectl get nodes -o wide`로 확인한다.

### 도메인과 인증서

| 도메인 | 가리키는 노드 | 용도 |
|---|---|---|
| `prod.assu.site` | prod | 운영 API |
| `dev.assu.site` | dev | 개발 API |
| `argocd.assu.site` | prod | ArgoCD UI |

- **Traefik은 DaemonSet이다.** prod·dev 노드에 1개씩 뜬다(control 제외).
  - `externalTrafficPolicy: Local`이라 각 노드는 자기 노드로 들어온 요청만 처리한다.
  - 한 노드가 죽어도 다른 노드의 서비스는 유지된다.
  - 예전에는 Traefik 1개가 dev 노드의 PVC에 묶여 있었다. 그래서 dev 노드를 내렸을 때 prod까지 다운된 장애가 있었다.
- **인증서는 cert-manager가 발급한다.**
  - ClusterIssuer `letsencrypt`가 HTTP-01 방식으로 발급한다.
  - Ingress에 `cert-manager.io/cluster-issuer: letsencrypt`와 `tls.secretName`을 적으면 Secret이 자동으로 발급·갱신된다.
  - Traefik 내장 ACME는 쓰지 않는다. 같은 챌린지 경로를 가로채 cert-manager와 충돌하기 때문이다.

### 저장소 3개

| 저장소 | 내용 | 반영 방식 |
|---|---|---|
| `ASSU_BE` (이 저장소) | 앱 소스, CI/CD 워크플로 | 머지 → 이미지 빌드 |
| `ASSU_BE_config` (`config` 서브모듈) | 환경별 `application-{profile}.yml` | **이미지에 포함된다.** 바꾸면 이미지를 다시 빌드해야 반영된다 |
| `ASSU_BE_manifest` | K8S 매니페스트, ArgoCD Application, 대시보드·알람 | 커밋하면 ArgoCD가 바로 반영한다 |

### ArgoCD Application

| 이름 | 대상 |
|---|---|
| `assu-prod-backend`, `assu-dev-backend` | `overlays/prod`, `overlays/dev` (앱, Redis, RabbitMQ, Alloy) |
| `assu-cluster-addons` | `cluster/` (Traefik 설정, ClusterIssuer, ArgoCD Ingress, 알림) |
| `cert-manager` | cert-manager Helm 차트 |
| `assu-cluster-monitoring` | 모니터링 구성 |

- 동기화 결과(배포 완료, 동기화 실패, health 저하)는 Discord로 알림이 간다(`cluster/argocd-notifications-cm.yml`).

## 3. 로그와 상태 확인

```bash
kubectl logs -n assu-prod -l app=assu-prod -f
kubectl logs -n assu-prod -l app=assu-prod --tail=200 --previous
kubectl logs rabbitmq-0 -n assu-prod --tail=100
kubectl logs redis-0 -n assu-prod --tail=100
kubectl describe pod <파드> -n assu-prod
kubectl get events -n assu-prod --sort-by=.lastTimestamp | tail -20
kubectl top pod -n assu-prod
```
- 크래시루프 중이면 `--previous`를 붙인다. 붙이지 않으면 방금 재시작한 컨테이너의 빈 로그만 보인다.
- Pending처럼 파드 자체가 뜨지 않으면 로그 대신 `describe`와 이벤트를 본다. ResourceQuota나 노드 자원 부족이 흔한 원인이다.
- dev는 namespace를 `assu-dev`, 라벨을 `app=assu-dev`로 바꿔서 같은 명령을 쓴다.
- 지표와 로그를 통합해서 보려면 [모니터링 가이드](모니터링가이드.md)를 참고한다.

### 헬스체크
앱은 management 포트(8081)로 probe를 받는다.

| probe | 경로 | DB 포함 | 실패 시 |
|---|---|---|---|
| readiness | `/actuator/health/readiness` | X | Traefik이 이 파드로 트래픽을 보내지 않음 |
| liveness | `/actuator/health/liveness` | X | 컨테이너 재시작 |
| startup (dev) | `/actuator/health/liveness` | X | 기동 완료 전까지 liveness 판정 보류 |

- 전체 상태를 보는 `/actuator/health`는 DB를 포함한다. probe에 쓰면 안 된다.
- 쓰면 안 되는 이유: DB가 느려졌을 때 앱이 트래픽에서 빠지고 재시작까지 돼서 장애가 커진다. 부하테스트에서 실제로 확인한 연쇄다.

## 4. DB / Redis / RabbitMQ 접속

### RDS (MariaDB)
- prod와 dev는 같은 RDS 인스턴스를 쓰고 스키마만 다르다.
- 로컬에서는 **SSM 포트포워딩**으로 접속한다. RDS 보안그룹을 열지 않는다.

PowerShell (Git Bash에서 백그라운드로 실행하면 세션은 열리지만 포트를 listen하지 않는다):
```powershell
Get-Content $HOME\.assu\infra.env | Where-Object { $_ -match '^\w+=' } | ForEach-Object { $k, $v = $_ -split '=', 2; Set-Item "env:$k" $v }
$params = "{`"host`":[`"$env:RDS_HOST`"],`"portNumber`":[`"$env:RDS_PORT`"],`"localPortNumber`":[`"13306`"]}"
Start-Process aws -ArgumentList @("ssm","start-session","--target",$env:SSM_TUNNEL_INSTANCE_ID,"--document-name","AWS-StartPortForwardingSessionToRemoteHost","--parameters",$params,"--region",$env:AWS_REGION) -WindowStyle Hidden
Get-NetTCPConnection -LocalPort 13306 -State Listen
```

```bash
source ~/.assu/infra.env
mysql -h 127.0.0.1 -P 13306 -u "$RDS_USER" -p "$RDS_DB_DEV" --default-character-set=utf8mb4
```
- 비밀번호는 `config/{dev,prod}/application-{profile}.yml`의 `spring.datasource.password`에 있다.
- **prod 스키마(`$RDS_DB_PROD`)에 쓰기 작업을 할 때:** SQL을 먼저 리뷰받고 트랜잭션 안에서 실행한다.
- 클러스터 안에서 확인해야 할 때는 임시 디버그 파드를 띄운다.
  - 네임스페이스에 ResourceQuota가 있으므로 `resources`를 반드시 지정한다.
  - 다 쓴 파드는 바로 삭제한다.

### Redis
```bash
kubectl exec -it redis-0 -n assu-prod -- redis-cli
```

### RabbitMQ Management UI

kubectl port-forward svc/rabbitmq -n assu-prod 15672:15672
kubectl get secret rabbitmq-auth -n assu-prod -o jsonpath='{.data.username}' | base64 -d; echo

## 5. 배포

### 정상 흐름
1. `develop`에 머지하면 dev에 배포된다. `main`에 머지하면 prod에 배포된다.
2. ArgoCD가 manifest 커밋을 감지해 반영한다.
   - prod는 RollingUpdate(`maxSurge 1`, `maxUnavailable 0`)라 무중단이다.
   - dev는 Recreate라 배포 중 잠시 503이 난다.
3. **배포 완료는 파드 기준으로 확인한다.** manifest 태그가 바뀐 것만으로는 배포가 끝난 게 아니다. 파드의 실제 이미지와 Ready 상태를 봐야 한다.
   ```bash
   kubectl get deploy assu-prod-app -n assu-prod -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
   kubectl get pods -n assu-prod -l app=assu-prod -o custom-columns=NAME:.metadata.name,IMAGE:.spec.containers[0].image,READY:.status.containerStatuses[0].ready
   ```
- 앱 기동에는 약 80초가 걸린다. 그 전에 Ready가 아니어도 정상이다.

### ArgoCD가 최신 커밋을 따라오지 못할 때
```bash
kubectl patch application assu-prod-backend -n argocd --type merge \
  -p '{"metadata":{"annotations":{"argocd.argoproj.io/refresh":"hard"}}}'
```

### 공유 dev 환경에서 측정할 때
- 부하테스트나 재현 실험 중에 develop에 머지하면 dev가 자동 재배포돼서 측정이 무효가 된다.
- 측정 시간 동안 머지를 멈추도록 먼저 공유한다.

## 6. 롤백과 장애 대응

### 롤백 (목표: 10분 안에)
1. `ASSU_BE_manifest`의 `overlays/prod/deployment-patch.yaml`에서 `image:` 태그를 직전 정상 SHA로 되돌리는 커밋을 push한다.
   - 직전 SHA는 `git log -p overlays/prod/deployment-patch.yaml`로 찾는다.
2. ArgoCD 반영이 늦으면 위의 hard refresh를 실행한다.
3. 파드 이미지와 Ready 상태로 롤백 완료를 확인한다.

- 클러스터에서 `kubectl set image`나 `kubectl edit`으로 직접 되돌리지 않는다. ArgoCD `selfHeal`이 git 상태로 다시 덮어쓴다.
- 앱 코드만 되돌리는 경우: `main`에 revert PR을 머지해도 되지만, 이미지 빌드 시간만큼 느리다. 급할 때는 manifest 태그를 되돌린다.

### 자주 겪는 장애

| 증상 | 원인 | 조치 |
|---|---|---|
| 노드 stop/start 후 도메인 접속 불가 | 공인 IP 변경 | 가비아 A 레코드 갱신 |
| 인증서 발급 실패, 웹훅 `x509` 오류 | k3s 재시작 중 cert-manager cainjector 비정상 | `kubectl rollout restart deploy -n cert-manager` |
| kubectl 무응답, API 타임아웃 | control 노드 메모리 부족 | control 재부팅. 아래 수동 설정이 적용돼 있는지 확인 |
| 이미지는 최신인데 파드가 이전 버전 | 오래 크래시루프한 파드가 교체되지 않음 | `kubectl delete pod <파드>` |
| 부하 시 503 | CPU throttling → HikariCP 고갈 → readiness 실패 | 모니터링 가이드의 용량 지표 확인. 앱 1대 한계는 약 초당 20~25건 |

### git에 없는 control 노드 수동 설정
노드를 새로 만들거나 k3s를 재설치하면 아래 설정을 다시 적용해야 한다. 모두 t3.small(2GB) 메모리를 아끼기 위한 설정이다.

| 위치 | 설정 |
|---|---|
| `/etc/rancher/k3s/config.yaml` | `kube-apiserver-arg`에 `event-ttl=15m`, `profiling=false` |
| `/etc/systemd/system/k3s.service.env` | `GOMEMLIMIT=500MiB` |
| ArgoCD | `argocd-dex-server`, `argocd-applicationset-controller` replicas 0 (SSO·ApplicationSet 미사용) |

| 키 | 용도 |
|---|---|
| `AWS_REGION` | AWS 리전 |
| `RDS_HOST`, `RDS_PORT`, `RDS_USER` | RDS 접속 |

| `SSM_TUNNEL_INSTANCE_ID` | SSM 포트포워딩 경유 인스턴스 |

| `CONTROL_HOST` | control 노드 주소 |
| `SSH_KEY_PATH` | SSH 키 경로 |
| `GRAFANA_URL`, `GRAFANA_STACK_NAMESPACE` | Grafana Cloud 스택 |

## 용어
| 용어 | 설명 |
|---|---|
| K3S | 경량 Kubernetes 배포판. control/prod/dev 3노드로 구성 |
| ArgoCD / GitOps | git 상태를 정답으로 삼아 클러스터를 자동으로 맞추는 도구와 방식 |
| Kustomize (base/overlays) | `base/`에 공통 뼈대를 두고, `overlays/{prod,dev}`가 이미지·리소스 차이만 patch한다 |
| Deployment / StatefulSet / DaemonSet | 상태 없는 앱 / 고유 저장소가 필요한 Redis·RabbitMQ / 노드마다 1개씩 뜨는 Traefik |
| PV / PVC (`local-path`) | 노드 로컬 디스크. 데이터가 있는 노드에서만 파드가 뜰 수 있어 사실상 노드에 고정된다 |
| nodeSelector / Taint·Toleration | "이 노드로 가라" / "이 노드엔 오지 마라"와 그 예외 |
| ResourceQuota | 네임스페이스 전체의 CPU·메모리·파드 수 상한 |
| Ingress / Traefik | 도메인별 라우팅 규칙과 그 규칙을 처리하는 프록시 |
| cert-manager / ClusterIssuer | Let's Encrypt 인증서 자동 발급·갱신 도구와 발급자 설정 |
| Secret | 비밀번호·키를 담는 K8S 리소스. git에 커밋하지 않고 클러스터에 직접 생성한다 |
